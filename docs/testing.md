# UniShare — Integration Testing & System Testing

**Project:** UniShare  
**Framework:** Laravel 11  

---

## 1. Integration Testing

Integration testing verifies that individual modules work correctly **together** as combined units, ensuring data flows correctly between components.

| Module Testing | Input Data | Error Handling | Expected Output |
| --- | --- | --- | --- |
| **Auth + User Management** | Valid credentials (`email`, `password`) submitted via `POST /login` | Returns error if credentials do not match any user record | User is authenticated, session created, and redirected to the Dashboard. |
| **Auth + User Management** | New user details (`name`, `email`, `phone_number`, `password`, `password_confirmation`) via `POST /register` | Checks for unique email and phone number; returns validation errors if password mismatch | User account is created with 100 starting points, user is logged in and redirected to Dashboard. |
| **Auth + Middleware** | Logged-in user with `is_suspended = 1` attempts to access the system | Middleware or login check detects suspended status | Access is denied; user cannot reach the Dashboard. |
| **Auth + Admin Middleware** | Logged-in user with `is_admin = 0` attempts to access `/admin/dashboard` | `AdminMiddleware` blocks the request | User is redirected away with an Access Denied error. |
| **Item Management + Database** | Item creation form (`title`, `category`, `description`, `condition`, `points_per_day`, `max_days`, `photos[]`) via `POST /items` | Rejects empty titles, non-image file uploads, and negative point values | Item saved to `items` table; uploaded photos saved to `item_photos` table with first photo set as primary. |
| **Item Management + Storage** | Editing an existing item with new photo uploads via `PATCH /items/{id}` | Fails with 403 if logged-in user does not own the item | Item record updated in `items` table; new photos appended to `item_photos`; no duplicate item created. |
| **Item Management + Photo Module** | Deleting the primary photo of an item via `DELETE /items/{id}/photos/{photoId}` | Rejects if photo does not belong to the item | Photo deleted from storage and `item_photos` table; next available photo automatically promoted as primary. |
| **Borrow Request + Points System** | Borrow request form (`item_id`, `start_date`, `end_date`, `points_per_day`) via `POST /borrow-requests` | Returns error "Item is not available for the selected dates" if dates overlap an existing active request | New `borrow_requests` record created with `status = pending`; no points deducted at this stage. |
| **Borrow Request + Points System** | Approving a pending borrow request via `PATCH /borrow-requests/{id}/approve` | Returns error if request is not in `pending` status; PointService throws error if borrower has insufficient points | Total points deducted from borrower; points credited to lender; status updated to `approved`; two `point_transactions` records created. |
| **Borrow Request + Points System** | Rejecting a pending borrow request via `PATCH /borrow-requests/{id}/reject` | Returns error if request is not in `pending` status | Status updated to `rejected`; no points transferred; no `point_transactions` records created. |
| **Borrow Request + Points System** | Cancelling an approved borrow request via `PATCH /borrow-requests/{id}/cancel` | Returns error "Only approved requests can be cancelled" if status is not `approved` | Points refunded to borrower; points reversed from lender; status updated to `cancelled`; two `point_transactions` records created. |
| **Borrow Request + Penalty System** | Lender marks item as returned via `PATCH /borrow-requests/{id}/returned` when current date exceeds `end_date` | Returns error if request is not in `borrowed` or `overdue` status | Status updated to `returned`; overdue days calculated; late penalty automatically created in `penalties` table (5 pts × overdue days); points deducted from borrower. |
| **Penalty System + Admin Module** | Lender submits damage report (`damage_description`, `evidence_photo`) via `POST /borrow-requests/{id}/report-damage` | Returns error if user is not the item owner; rejects if item status is not `returned`, `borrowed`, or `overdue`; requires evidence photo | Penalty record created in `penalties` table with `status = pending`; no points deducted until admin approves. |
| **Penalty System + Admin Module** | Lender marks item as missing (`evidence_photo`) via `POST /borrow-requests/{id}/missing` | Returns error if user is not the item owner; rejects if request cannot transition to `missing` status | Borrow request status updated to `missing`; penalty record created in `penalties` with `status = pending`. |
| **Admin Module + Points System** | Admin approves a pending penalty via `POST /admin/penalties/{id}/approve` | Returns error if penalty is not in `pending` status | Penalty status updated to `active`; penalty points deducted from borrower; lender compensated for `damaged` and `missing` types; `point_transactions` records created for both users. |
| **Admin Module + Points System** | Admin rejects a pending penalty via `POST /admin/penalties/{id}/reject` | Returns error if penalty is not in `pending` status | Penalty status updated to `rejected`; no points deducted; if type was `missing`, borrow request status reverted to `borrowed` or `overdue`. |
| **Admin Module + User Management** | Admin suspends a user (`reason`) via `POST /admin/users/{id}/suspend` | Returns error if admin tries to suspend themselves or another admin | User `is_suspended` set to `1`; `suspended_at` and `suspension_reason` fields updated in `users` table. |
| **Admin Module + User Management** | Admin unsuspends a user via `POST /admin/users/{id}/unsuspend` | No action if user is not currently suspended | User `is_suspended` set to `0`; `suspended_at` and `suspension_reason` cleared. |
| **Admin Module + Points System** | Admin adjusts user points (`points`, `reason`) via `POST /admin/users/{id}/adjust-points` | Validates that points field is an integer | User `points_balance` updated by the specified amount; `point_transactions` record created with `type = adjustment`. |
| **Admin Module + Item Module** | Admin deletes an item via `DELETE /admin/items/{id}` | Returns error if item does not exist | Item removed from `items` table; all associated `item_photos` cascade deleted from storage and database. |
| **Messaging System + Conversation Module** | Starting a new conversation (`recipient_id`, `message`) via `POST /messages/start` | Prevents messaging yourself; returns error if recipient does not exist | New `conversations` record created; first `messages` record stored; user redirected to the conversation thread. |
| **Messaging System + Conversation Module** | Sending a message in an existing thread (`conversation_id`, `message`) via `POST /messages` | Returns 403 if sender is not part of the conversation | New `messages` record appended to existing conversation; no duplicate `conversations` record created. |
| **Messaging System + Read Status** | Recipient opens a conversation thread via `GET /messages/{conversation}` | Returns 403 if user is not a participant of the conversation | All unread messages from the other user have `read_at` timestamp set to the current time. |
| **Rating + Review System** | Borrower submits a review (`rating`, `comment`) on a returned borrow request | Returns error if user already reviewed the same borrow request (unique constraint on `reviewer_id`, `borrow_request_id`) | Review stored in `reviews` table; visible on the item detail page. |
| **Rating + User Reputation** | User submits a user-to-user rating (`rating` 1–5) after a borrow transaction | Returns error if user attempts to rate the same request twice (unique constraint on `rater_id`, `borrow_request_id`) | Rating stored in `ratings` table; rated user's average reputation score recalculated on their profile. |

## 2. System Testing

System testing validates the **complete end-to-end functionality** of UniShare as a whole, from the user's perspective.

| Module Testing | Input Data | Error Handling | Expected Output |
| --- | --- | --- | --- |
| **New Student Registration & Login** | Full registration form (`name`, `email`, `phone_number`, `password`) followed by login with same credentials | Rejects duplicate email/phone; validates password confirmation match | Account created with 100 starting points; user successfully logged in and lands on Dashboard showing active items. |
| **Complete Item Listing Flow** | Item details form (`title`, `category`, `description`, `condition`, `points_per_day`, `max_days`) with 2 uploaded photos | Rejects empty title, non-image files, and invalid points values | Item saved and listed as Active; primary photo displayed on item card in Dashboard; item visible to other users. |
| **Full Borrow & Return Transaction** | Borrow request form (dates, `item_id`) → lender approves → lender marks borrowed → lender marks returned (on time) | Blocks request if dates overlap; blocks approval if borrower has insufficient points | Points correctly deducted from borrower and credited to lender on approval; status progresses through `pending → approved → borrowed → returned`; no penalty applied on time return. |
| **Overdue Return with Auto Late Penalty** | Lender marks item as returned after the `end_date` has passed | Returns error if item is not in `borrowed` or `overdue` status | Overdue days calculated correctly; late penalty auto-created (5 pts × overdue days); points deducted from borrower; status updated to `returned`. |
| **Damage Report & Admin Penalty Approval** | Lender submits damage report with `damage_description` and `evidence_photo`; admin reviews and approves | Requires lender ownership; requires evidence photo file; rejects approval if penalty is not `pending` | Penalty created with `status = pending` (no points deducted yet); after admin approval, 50 points deducted from borrower and credited to lender; `point_transactions` records created for both. |
| **Admin Rejects Penalty Report** | Admin navigates to Penalties panel and clicks Reject on a `pending` penalty | Returns error if penalty is not in `pending` status | Penalty status updated to `rejected`; borrower's points remain unchanged; lender receives no compensation. |
| **Missing Item Report & Admin Approval** | Lender uploads `evidence_photo` and submits missing item report; admin reviews and approves | Requires lender ownership; requires evidence photo; blocks if request cannot transition to `missing` | Borrow request status → `missing`; penalty created as `pending`; admin approval deducts penalty points from borrower and compensates lender. |
| **Full Messaging Flow** | User A sends message to User B via item detail page; User B replies in thread | Prevents messaging self; blocks access to conversations the user is not part of | Conversation thread created; both messages stored; unread badge shown on navbar; `read_at` set when message is viewed. |
| **Admin Suspends & Unsuspends Account** | Admin enters suspension reason and submits; later clicks Unsuspend on the same user | Cannot suspend another admin or yourself | While suspended, user cannot log in; after unsuspending, user can log in and access the system normally. |
| **Admin Manually Adjusts User Points** | Admin enters `+50` points with reason "Bonus Award"; then `-20` points with reason "Penalty correction" | Validates that the points field is an integer | User's `points_balance` increases by 50 then decreases by 20; two `point_transactions` records created with `type = adjustment`. |
| **Item Search and Category Filter** | Search keyword "Camera" entered in search bar; category "Electronics" selected from dropdown | No error thrown if search returns zero results; displays empty state message | Search results show only matching items; category filter narrows list correctly; clearing filters restores the full item listing. |
| **Review & Rating After Completed Borrow** | Borrower submits 5-star review with comment; rates lender 4 stars | Blocks duplicate review or rating for same borrow request | Review appears on item detail page; user-to-user rating stored; lender's average reputation score updated on their profile. |
| **Admin Reports & Analytics Dashboard** | Admin navigates to Reports page (no input required) | No crash if tables have zero data | All report sections load: top lenders, top borrowers, most popular items, category distribution chart, and monthly transaction trends. |
| **Item Availability Conflict Prevention** | Second user submits borrow request for same item with overlapping dates (e.g. existing booking: May 1–5; new request: May 3–7) | Returns error "Item is not available for the selected dates" | New borrow request is rejected; no record created in `borrow_requests`; existing booking remains unaffected. |
| **Full Profile Update with Avatar** | User submits updated `name`, `bio`, `location`, and uploads a new `avatar` image via `PATCH /profile` | Validates unique email (excluding self); accepts only valid image file types for avatar | Profile updated in `users` table; new avatar stored in public storage; updated information displayed correctly on profile page. |
| **Admin Toggle Item Status** | Admin navigates to Items panel and clicks Activate/Deactivate on any item | Returns error if item does not exist | Item `is_active` toggled; deactivated items no longer appear in the student Dashboard browse; activated items become visible again. |
| **Favourite / Like an Item** | Logged-in user clicks Like on an item via `POST /items/{id}/like` | Handles cases where item is already liked (toggles off instead of duplicate) | Item added to user's liked items list in `user_item_likes`; clicking again removes the like (toggle behaviour). |
